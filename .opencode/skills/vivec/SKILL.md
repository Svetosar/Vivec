# Vivec — школьная газета (мини-CMS)

Проект под кодовым именем **Vivec**. Название — отсылка к TES III: Morrowind, Вивек — один из богов Трибунала. Это не про город Вивек и не про что-либо ещё.

## 0. Контекст, который нельзя перепутать

| Что | Значение |
|---|---|
| Что делаем | Сайт школьной газеты + мини-CMS: статьи в Markdown, загрузка через веб-админку |
| Сдача | **30.11.2026**. Старт 14.11.2026. Бюджет **2–3 часа в день** |
| Пользователь | Сисадмин. Rust и JS — с нуля. Не «заказчик», а исполнитель, который учится |
| Роль агента | Наставник + ревьюер + ускоритель. **Не** генератор «всё сразу» |
| Сервер | 1 ГБ ОЗУ, Caddy на 443, 3x-ui за реверс-прокси (VPN на отдельном порту) |
| Боевой домен | Не зафиксирован. Спросить, не придумывать |
| Локальная машина | Gentoo + OpenRC, `doas` (не sudo), podman 6.1.4, rust 1.98, node 26, 4 ядра / 15 ГБ |
| Сервер: ОС и init | **Неизвестно.** Уточнить до деплоя. Не писать `systemctl` как факт, пока не подтверждено |

Главный риск проекта — не сложность Rust, а расползание объёма. Скоуп защищаем жёстко.

## 1. Железные правила

1. **Проверять, а не выдумывать.** API крейтов и фреймворков — через context7 или официальные доки. Поведение — запустить и посмотреть. Если не проверял — так и сказать: «не проверял».
2. **Опасное — спрашивать.** Обязательно перед:
   - `git push --force`, `rebase`/`reset` на `main`, удаление веток и тегов;
   - миграции с `DROP`/переименованием колонок на проде;
   - `rm -rf`, чистка `data/`, перезапись `/etc/caddy/Caddyfile`;
   - любые действия с 3x-ui, VPN и сетевой конфигурацией сервера;
   - деплой, если пользователь в этот момент что-то правит;
   - добавление новой зависимости (обосновать, что не решается 20 строками).
3. **`main` — только проверенный код.** Вся работа в ветках.
4. **`TODO.md` ведётся всегда.** Перед задачей — прочитать, после — обновить.
5. **Правило 30 строк.** Не давать блок кода >30 строк, который пользователь не сможет пересказать. Сначала объяснить идею, потом код.
6. **Скоуп заморожен 26.11.** Новые идеи идут в `docs/backlog.md`, а не в код.

## 2. Git-процесс

- Ветки: `feature/<кратко>`, `fix/<кратко>`, `chore/<кратко>`. Одна фича = одна ветка.
- Начало работы: `git switch main && git pull --ff-only && git switch -c feature/<имя>`.
- Коммиты: Conventional Commits — `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `deploy:`. Заголовок короткий, тело по-русски при необходимости.
- Каждый обычный и merge-коммит заканчивается отдельной строкой `AI-assisted: Codex`. Без пометки коммит не создавать.
- Мерж в `main` только `--no-ff`, только после чек-листа из `references/checklists.md` и явного «да» пользователя.
- Релиз = тег `v0.x.y` на `main` + деплой.
- Перед коммитом: `git status` и `git diff --staged` глазами. Никогда не коммитить `data/`, `.env`, `target/`, `node_modules/`, `dist/`, `static/admin/`.
- Никогда не переписывать историю, которая уже ушла в `origin`.

## 3. Стек зафиксирован. Менять — только с явного разрешения

| Слой | Выбрано | Запрещено |
|---|---|---|
| HTTP | `axum` 0.8 | actix, rocket, warp |
| Async | `tokio` | async-std, smol |
| БД | SQLite + `sqlx`, runtime-запросы | Diesel, SeaORM, Postgres, MongoDB |
| Шаблоны | `minijinja` + `include_str!` | askama (лайфтаймы), tera |
| Markdown | `pulldown-cmark` + `ammonia` | рендер на клиенте, без санитайзинга |
| Пароли | `argon2` | самописное, md5, sha1 |
| Статика | `tower-http::ServeDir` | встраивание через rust-embed |
| Публичный фронт | SSR HTML, ноль JS-зависимостей | SPA, React, гидрация |
| Админка | Vue 3 + Vite + vue-router + `md-editor-v3` | PrimeVue, Pinia, TypeScript, Nuxt |
| Даты | `TEXT` + `datetime('now')` в SQLite | `chrono`/`time` в типах struct |
| Ошибки | `enum AppError` + `IntoResponse` | `anyhow` в хендлерах |
| Деплой | rootless podman + Quadlet + Caddy | Docker, docker-compose, k8s, сборка на сервере |

Правило: меньше зависимостей — меньше ошибок. Новая зависимость = отдельный вопрос пользователю.

## 5. Шесть паттернов Rust — всё остальное не нужно

Канонические образцы живут в `src/`, а не в этом скилле (чтобы не расходились с кодом). При добавлении файла — копировать ближайший существующий, а не писать с нуля.

1. Хендлер страницы: `query_as` → `render` → `Html`.
2. Хендлер формы: `Form<T>` → валидация → `INSERT` → `Redirect`.
3. Хендлер JSON API: `Json<T>` на вход/выход.
4. Загрузка файла: `Multipart` → `infer` → `fs::write`.
5. Авторизация: middleware + cookie + сессия в БД.
6. Миграция: `.sql` файл + `sqlx::migrate!`.

Запрещено без отдельного разрешения: generics, traits, макросы, trait objects, `unsafe`, кастомные `Future`, ручное управление лайфтаймами.

## 6. Правила кода

**Rust**
- Строки — `String`, не `&'a str`. Лайфтаймы не воевать, а обходить.
- Каждый хендлер возвращает `Result<_, AppError>`.
- SQL только параметризованный: `.bind(x)`, никогда `format!`.
- Валидация входа на границе + лимиты размеров.
- `cargo check` до `cargo run`. Перед мержем — `cargo clippy -- -D warnings`.
- Никаких комментариев-очевидностей. Комментарий объясняет «почему», а не «что».

**Vue**
- Composition API, `<script setup>`, без Pinia (хватает composable).
- Все запросы — через один `api.js`: `credentials: 'include'`, обработка 401 → редирект на логин.
- В UI нет бизнес-логики. Валидация дублируется на сервере всегда.

**Безопасность (не обсуждается)**
- Markdown всегда проходит `ammonia`.
- Пароль — только `argon2`; никаких своих хешей.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` в проде.
- CSRF: `SameSite=Lax` + обязательный кастомный заголовок на JSON-мутациях.
- Загрузки: тип по магии (`infer`), лимит 8 МБ, случайное имя файла, расширению не верить.
- Секреты — только в `deploy/vivec.env` на сервере. В репо — `.example`.
- Лимит попыток логина — по имени пользователя (за Caddy IP клиента не гарантирован).

## 7. Проверка перед словом «готово»

- [ ] `cargo check` без ошибок, `cargo clippy` без предупреждений
- [ ] Приложение запущено, затронутые роуты дёрнуты `curl`
- [ ] Миграции применяются на **чистой** БД
- [ ] UI проверен в браузере, включая мобильную ширину
- [ ] `scripts/smoke.sh` проходит
- [ ] Для незнакомого API — сверка с докой (context7 / официальный сайт)
- [ ] В диффе нет секретов, `data/`, сборок

**Никогда не говорить «работает», не запустив.** Никогда не цитировать API по памяти, если версия могла измениться.

## 8. Definition of Done для фичи

Работает → проверено вручную → нет новых предупреждений → понятно пользователю → закоммичено в ветку → отмечено в `TODO.md`. Всё четыре пункта, иначе фича не готова.

## 9. Деплой и эксплуатация

- Деплой только через `scripts/deploy.sh`: сборка локально → `podman save | ssh | podman load` → `systemctl --user restart vivec` → `/healthz` → откат при провале.
- Перед деплоем: бэкап БД, зафиксированный коммит/тег.
- После деплоя: `/healthz`, главная, логин, **панель 3x-ui жива**.
- Данные: `/srv/vivec/data` (БД + uploads). Бэкап ежедневно, восстановление проверять руками раз в неделю.
- Сборка на сервере (1 ГБ) **запрещена** — только локально.
- Caddyfile: править блоками, `caddy validate` перед `systemctl reload caddy`, никогда не `restart` при живой панели.

## 10. Взаимодействие с пользователем

- Русский язык, коротко, без воды и без похвалы ради похвалы.
- Ошибку компилятора объяснять, а не «вот исправленный файл».
- Один вопрос за раз, если он блокирует. Остальное — предположение с пометкой.
- Не обещать сроков, которых нет. Если не влезает — сказать сразу и предложить, что резать.
- Обучать на его же коде: новая концепция объясняется на файле, который он только что написал.

## 11. Антипаттерны

- «Давай перепишем на другом стеке» — нет.
- Зависимость ради 10 строк — нет.
- Оптимизация до работающего прототипа — нет.
- Тесты ради покрытия — нет (smoke + чек-лист).
- Код «на будущее» и абстракции без второго применения — нет.
- Сборка в контейнере на сервере, docker-compose, k8s — нет.
- Молчаливое изменение схемы БД — нет.

## 12. Протокол TODO

`TODO.md` в корне, разделы: `Сейчас`, `Дальше`, `Потом`, `Сделано`.
Перед сессией — прочитать. После задачи — отметить и записать новое. Список никогда не живёт только в голове.

## 13. Журнал, решения и обучение

Проект почти весь из нового, поэтому память ведётся письменно, а не «в голове».

**Правила:**
1. В конце каждой рабочей сессии — запись в `docs/journal.md`: сделано → новое → сломалось → урок → дальше. 5 минут, обязательно, даже если день провальный.
2. Любая ловушка (ошибка компилятора, странность крейта, поведение Caddy/podman) — в `docs/gotchas.md` со статусом `проверено` / `гипотеза` / `решение`. Гипотезу нельзя выдавать за факт, пока не воспроизвели.
3. Грабли, повторившиеся дважды, переносятся в этот скилл, чтобы не наступить третий раз.
4. Перед задачей: прочитать `TODO.md` и последнюю запись журнала. После задачи: дописать журнал.
5. Раз в неделю (по воскресеньям) — 10 минут ревизии: что в журнале повторилось, что пора поднять в скилл.
6. Старые записи не переписывать. Ошибки в журнале — это данные, а не стыд.
