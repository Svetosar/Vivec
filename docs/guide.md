# Vivec: подробный учебный гайд по проекту

Этот документ объясняет проект целиком и рассчитан на человека, который
только начинает изучать Rust, JavaScript, HTTP и SQL. Его не нужно читать
всё сразу. Сначала прочитай разделы 1–5, потом разбирай по одному файлу
из `src/`. Перед каждой правкой возвращайся к разделу «Как учиться».

Главное правило проекта: не говорить «работает», пока код не проверен
командой, запуском и HTTP-запросом.

---

## 1. Что такое Vivec

Vivec — школьная газета с небольшой системой управления статьями.

У проекта две разные части:

| Часть | Адрес | Как сделана | Зачем |
|---|---|---|---|
| Публичная газета | `/`, `/rubric/...`, `/{slug}` | HTML собирается на сервере | Быстро, надёжно, работает без JS |
| Админка | `/admin/` | Будет Vue 3 SPA | Редактору нужно динамическое приложение |
| API админки | `/api/admin/...` | Rust + JSON | Vue отправляет данные и получает ответы |

`SSR` значит Server-Side Rendering: сервер сам заполняет HTML статьёй и
отправляет браузеру готовую страницу. Публичной части не нужен JavaScript,
чтобы показать статью.

`SPA` значит Single Page Application: браузер один раз загружает приложение,
а затем меняет экран без полной перезагрузки страницы. Такой будет админка.

Почему нельзя сделать всю газету SPA на JavaScript:

- поисковые системы и старые устройства должны получать готовый HTML;
- публичная статья не должна зависеть от загрузки большого JS;
- у сервера уже есть база и шаблоны, это проще и надёжнее.

Почему админку всё же делаем на Vue:

- форма статьи постоянно меняет состояние;
- нужен предпросмотр Markdown;
- нужны загрузка изображений, таблицы и навигация без перезагрузок.

## 2. Технологии простыми словами

| Технология | Что делает в Vivec |
|---|---|
| Rust | Язык backend-сервера |
| axum | HTTP-роутер: связывает URL с Rust-функцией |
| tokio | Асинхронный runtime, который запускает сервер |
| SQLite | База данных в одном файле |
| sqlx | Rust-запросы к SQLite |
| minijinja | Шаблоны HTML |
| pulldown-cmark | Markdown превращает в HTML |
| ammonia | Убирает опасный HTML |
| argon2 | Хеширует пароль администратора |
| Vue 3 | JavaScript-приложение админки |
| Vite | Dev-сервер и сборщик Vue |
| md-editor-v3 | Markdown-редактор с предпросмотром |
| podman | Контейнер для запуска на сервере |
| Caddy | HTTPS и reverse proxy перед контейнером |

Слово «backed» на практике означает:

1. принять HTTP-запрос;
2. проверить входные данные;
3. прочитать или изменить SQLite;
4. вернуть HTML либо JSON;
5. записать ошибку в лог, если что-то сломалось.

## 4. Как проходит запрос

Публичная главная страница:

```text
Браузер
  → GET /
  → Caddy (на проде) или напрямую axum (локально)
  → Router выбирает index()
  → articles::published()
  → SQLite SELECT
  → Markdown превращается в безопасный HTML
  → minijinja заполняет index.html.jinja
  → axum отправляет HTML и статус 200
```

Страница статьи:

```text
GET /remont-sportzala
  → article()
  → articles::by_slug()
  → SELECT ... WHERE slug = ? AND published = 1
  → если строки нет: страница 404
  → если строка есть: article.html.jinja
```

Поиск:

```text
GET /search?q=ремонт
  → search()
  → articles::search()
  → published=1
  → Unicode to_lowercase().contains() в Rust
  → search.html.jinja
```

SQLite `LIKE`/`NOCASE` без ICU не меняет регистр кириллицы, поэтому фильтрация
выполняется в Rust. Черновики не попадают в поиск.

Вход в админку:

```text
POST /api/admin/login
  → JSON с username/password
  → Argon2 проверяет пароль
  → создаётся случайный токен
  → в БД сохраняется SHA-256 токена
  → браузер получает HttpOnly cookie
  → следующие запросы приносят cookie
  → middleware проверяет сессию в БД
```

### HTTP-методы

| Метод | Смысл | Пример |
|---|---|---|
| GET | Прочитать | Открыть статью |
| POST | Создать или выполнить действие | Создать статью, войти |
| PUT | Полностью обновить | Сохранить форму статьи |
| DELETE | Удалить | Удалить статью |

### HTTP-статусы в проекте

| Код | Значение |
|---|---|
| 200 | Успех |
| 201 | Объект создан |
| 204 | Успех без тела ответа |
| 400 | Клиент передал неверные данные |
| 401 | Нужно войти |
| 403 | Вход есть, действие запрещено |
| 404 | Не найдено |
| 409 | Конфликт, например одинаковый slug |
| 413 | Слишком большое тело запроса |
| 429 | Слишком много попыток входа |
| 500 | Внутренняя ошибка сервера |
| 503 | Сервис ещё не настроен |

Нельзя возвращать `200` на ошибку. Браузер, мониторинг и тесты должны
понимать проблему по коду ответа.

## 5. Минимум Rust, без которого проект не понять

### 5.1 Rust компилируется заранее

JavaScript-браузер обычно читает файл и выполняет его. Rust сначала
проверяет типы, владение и заимствования, затем создаёт машинный бинарник.

Поэтому:

- `cargo check` ловит ошибки без полной сборки;
- `cargo build` создаёт `target/debug/vivec`;
- `cargo test` собирает и запускает тесты;
- `cargo clippy` ищет подозрительные места;
- ошибка компилятора часто точнее, чем сообщение в браузере.

### 5.2 `Cargo.toml` и crates

`crate` — библиотека или пакет Rust на crates.io.

```toml
axum = "0.8.9"
serde = { version = "1.0.229", features = ["derive"] }
```

Строка значит: взять axum версии 0.8.9. У serde дополнительно включена
возможность автоматически создавать код сериализации через `derive`.

Новую зависимость нельзя добавлять молча: она увеличивает сборку, риск
уязвимостей и объём, который нужно понимать.

### 5.3 `mod`, `use` и модули

В `main.rs` есть:

```rust
mod articles;
mod auth;
```

Это означает «подключить файл `src/articles.rs` или `src/auth.rs`».

`use` сокращает длинные имена:

```rust
use crate::error::AppError;
```

`crate` здесь означает текущий Rust-пакет Vivec.

### 5.4 Владение и заимствование

У `String` есть владелец. Если передать `String` в функцию, владение
может перейти туда:

```rust
fn clean(value: String) -> String {
    value.trim().to_string()
}
```

Если функция должна только прочитать строку, используется ссылка:

```rust
fn clean(value: &str) -> String {
    value.trim().to_string()
}
```

В проекте:

- `&str` — временный взгляд на строку;
- `String` — собственные данные, которыми владеет структура;
- `&app.pool` — функция читает пул, но не забирает его;
- `app.clone()` — делает дешёвую копию handles состояния.

`App` содержит пул БД, шаблоны и настройки auth. В axum каждый запрос
получает свою копию `App`. Внутри пул и лимитер входа устроены так, что
копия не дублирует базу и память целиком.

### 5.5 `Option<T>`

`Option<T>` означает «T есть или T нет».

```rust
Option<String>
```

В проекте `published_at` может быть `None` у черновика. Нельзя случайно
использовать отсутствующую дату: компилятор заставит обработать оба случая.

### 5.6 `Result<T, E>`

`Result<T, E>` означает «успех T или ошибка E».

```rust
Result<Json<Article>, AppError>
```

Вопросительный знак:

```rust
let html = template.render(ctx)?;
```

означает: если операция вернула ошибку, немедленно выйти из функции,
преобразовав ошибку в `AppError`.

### 5.7 Struct, enum, match

`struct` объединяет поля:

```rust
struct UserResponse {
    username: String,
}
```

`enum` означает одно из нескольких состояний:

```rust
enum AppError {
    BadRequest(&'static str),
    Unauthorized,
    NotFound,
}
```

`match` гарантирует, что обработан каждый вариант. Если добавить вариант
ошибки и забыть про него, компилятор предупредит.

### 5.8 Итераторы

Код:

```rust
row.map(to_article).transpose()
```

Если строки нет, получается `Ok(None)`. Если строка есть, `to_article`
создаёт `Article` или ошибку, и получается `Ok(Some(article))` либо `Err`.

Итераторы используются вместо ручных циклов, когда нужна простая цепочка
преобразований.

### 5.9 `async` и `await`

Запрос к базе и сетевой ответ не блокируют весь сервер. Функция с `async`
возвращает будущее вычисление. `await` означает «подожди результат, но
пусть tokio пока выполнит другие задачи».

Нельзя долго держать `std::sync::Mutex` во время `await`: это может
заблокировать другие запросы. В auth блокировка лимитера освобождается
до работы с базой.

## 6. Разбор `src/main.rs`

### 6.1 Константы шаблонов

```rust
const LAYOUT: &str = include_str!("../templates/layout.html.jinja");
```

`include_str!` вставляет содержимое файла в бинарник на этапе компиляции.
После правки шаблона нужен новый `cargo build`/`cargo run`.

Плюс: в контейнере не бывает ситуации «шаблон потерялся».
Минус: HTML нельзя поменять без пересборки приложения.

### 6.2 `App`

```rust
#[derive(Clone)]
struct App {
    tpl: minijinja::Environment<'static>,
    pool: SqlitePool,
    auth: auth::Auth,
}
```

Это состояние, доступное хендлерам через `State<App>`.

- `tpl` хранит загруженные шаблоны;
- `pool` выдаёт соединения SQLite;
- `auth` знает настройки входа и хранит лимиты попыток.

`#[derive(Clone)]` создаёт реализацию клонирования, чтобы axum мог передать
состояние каждому запросу.

### 6.3 Порядок запуска

`main()`:

1. включает логи `tracing`;
2. открывает базу через `db::open()`;
3. регистрирует HTML-шаблоны;
4. создаёт `App`;
5. собирает публичный роутер;
6. собирает защищённый admin API;
7. добавляет раздачу `/static`;
8. читает `PORT`;
9. начинает слушать HTTP;
10. корректно завершает работу по Ctrl+C/SIGTERM.

### 6.4 Роутер

Упрощённо:

```rust
Router::new()
    .route("/", get(index))
    .route("/healthz", get(healthz))
    .route("/rubric/{rubric}", get(rubric))
    .route("/{slug}", get(article))
    .nest("/api/admin", admin_api)
```

`{rubric}` и `{slug}` — параметры URL. axum 0.8 использует фигурные скобки,
а не старый синтаксис `:slug`.

`/{slug}` должен идти после `/rubric/...`, иначе короткие и динамические
маршруты могут конкурировать непредсказуемо.

### 6.5 Защищённый API

Защищённые маршруты находятся в отдельном `Router`, к которому применён
`route_layer(middleware::from_fn_with_state(...))`.

Middleware пропускает запрос дальше только после успешной проверки cookie
и сессии. Login находится снаружи, иначе войти было бы невозможно.

### 6.6 Публичные хендлеры

`index()`:

- получает опубликованные статьи;
- первую делает героем;
- следующие три — карточками;
- создаёт `IndexCtx`;
- рендерит шаблон.

`article()`:

- ищет опубликованную статью по slug;
- черновик и несуществующий slug одинаково дают 404;
- рендерит статью либо общую страницу 404.

`rubric()`:

- проверяет slug рубрики по фиксированному списку;
- получает статьи этой рубрики;
- неизвестная рубрика тоже даёт 404.

### 6.7 Graceful shutdown

`shutdown_signal()` ждёт Ctrl+C или SIGTERM. `with_graceful_shutdown`
позволяет завершить текущие запросы до остановки процесса.

Без этого контейнер после `podman stop` мог висеть 10 секунд и обрывать
соединения. Это уже проверено в проекте.

## 7. SQLite, SQL и `src/db.rs`

### 7.1 Что такое база и пул

SQLite хранит всю базу в файле `data/vivec.db`.

Пул соединений — набор готовых соединений, которые переиспользуются между
запросами. Создавать соединение заново на каждый HTTP-запрос слишком дорого.

`SqliteJournalMode::Wal` включает Write-Ahead Logging. Читатели и писатель
меньше мешают друг другу. Рядом с `vivec.db` могут появиться `vivec-wal`
и `vivec-shm` — это нормально.

### 7.2 Путь к данным

```text
DATA_DIR не задан → data/vivec.db
DATA_DIR=/data   → /data/vivec.db
```

В контейнере используется `/data`, на хосте это `/srv/vivec/data`.
Каталог данных не коммитится.

### 7.3 Схема статей

`migrations/0001_init.sql` создаёт таблицу `articles`.

| Колонка | Смысл |
|---|---|
| `id` | Уникальный номер |
| `slug` | Часть URL, например `remont-sportzala` |
| `title` | Заголовок |
| `rubric` | Русское имя рубрики |
| `author` | Автор |
| `lead` | Короткое описание |
| `body_md` | Исходный Markdown |
| `published` | 0 — черновик, 1 — опубликовано |
| `published_at` | Дата публикации или NULL |
| `created_at` | Дата создания |

`UNIQUE` на slug не даёт двум статьям иметь один URL.

Индекс `idx_articles_published` ускоряет типичный запрос: только
опубликованные статьи, свежие сверху.

### 7.4 Схема сессий

`migrations/0002_admin.sql` создаёт `sessions`.

В таблице лежит `token_hash`, а не сам пароль и не сырой токен cookie.
Если база утечёт, значение из таблицы нельзя просто подставить в cookie.

`expires_at` позволяет удалять старые сессии.

### 7.5 Почему `CREATE TABLE IF NOT EXISTS`

Схема применяется при старте. Повторный запуск не должен падать из-за
того, что таблица уже создана.

Это простой механизм для текущего масштаба. Если позже понадобится менять
колонки существующей таблицы, следует перейти на полноценный migration
runner и отдельно проверять каждую миграцию на копии продовой базы.

### 7.6 Параметризованный SQL

Правильно:

```rust
sqlx::query("SELECT ... WHERE slug = ?")
    .bind(slug)
```

Неправильно:

```rust
format!("SELECT ... WHERE slug = '{slug}'")
```

Второй вариант позволяет внедрить SQL-код через slug. В проекте все
пользовательские значения передаются через `.bind`.

## 8. Чтение статей: `src/articles.rs`

### 8.1 Рубрики

`RUBRICS` — фиксированный массив пар:

```text
русское имя ↔ slug
```

Так `/rubric/shkola` существует, а `/rubric/net-takoy` получает 404.

### 8.2 `Article`

Публичная структура статьи содержит уже не `body_md`, а `body_html`.
Это важно:

- SQLite хранит исходный Markdown;
- на границе приложения он безопасно превращается в HTML;
- шаблон получает готовое тело.

`rubric_slug` вычисляется из русского имени через `slug::translit`.

### 8.3 Запросы

`published()`:

```sql
WHERE published = 1
ORDER BY published_at DESC, id DESC
```

Самые свежие опубликованные статьи идут первыми.

`by_slug()` дополнительно требует `published = 1`. Поэтому черновик нельзя
открыть, даже если знать его slug.

`by_rubric()` сначала получает опубликованные статьи, затем фильтрует их
в Rust. Для школьной газеты это дешевле, чем отдельная колонка slug рубрики.

### 8.4 `try_get`

`Row::try_get` читает колонку по имени и возвращает ошибку, если имя или
тип не совпали. Это runtime-запрос: SQL проверяется при выполнении, а не
при компиляции. Поэтому после нового запроса обязательно нужен живой
HTTP-тест.

### 8.5 Русская дата

SQLite отдаёт `2026-11-12`. Функция `ru_date` превращает это в
`12 ноября`. Ведущий ноль убирается: `05` становится `5`.

Если дата пустая или битая, возвращается пустая строка. Это лучше, чем
показать `undefined`.

## 9. Markdown и защита от XSS

`src/markdown.rs` делает два шага:

1. pulldown-cmark превращает Markdown в HTML;
2. ammonia очищает этот HTML.

Почему одного Markdown-парсера мало: pulldown-cmark разрешает сырой HTML.
Без очистки автор мог бы вставить `<script>`.

Ammonia оставляет безопасный набор тегов: заголовки, списки, ссылки,
цитаты, изображения и другие обычные элементы статьи.

В шаблоне статьи:

```jinja
{{ article.body_html | safe }}
```

`safe` запрещает Jinja повторно экранировать HTML. Это допустимо только
потому, что строка уже прошла ammonia.

Проверенные правила:

- `<script>` удаляется;
- `onerror` удаляется;
- `javascript:` ссылки удаляются;
- относительное изображение `/uploads/...` сохраняется.

Любая новая настройка ammonia должна проверяться реальным XSS-тестом.

## 10. Транслитерация slug: `src/slug.rs`

Slug — человекочитаемая часть URL:

```text
День самоуправления
→ den-samoupravleniya
```

Алгоритм:

1. привести строку к нижнему регистру;
2. каждую кириллическую букву заменить латиницей;
3. ASCII-буквы и цифры оставить;
4. группы пробелов и знаков заменить одним `-`;
5. убрать дефисы в конце.

Функция не гарантирует уникальность. Уникальность обеспечивает `UNIQUE`
в SQLite и проверка API с ответом `409`.

Тесты внизу файла — пример того, как закреплять правила, которые легко
сломать случайной правкой.

## 11. Ошибки: `src/error.rs`

Хендлеры возвращают `Result<..., AppError>`. В ошибке хранится понятная
причина, а `IntoResponse` выбирает HTTP-статус.

Важное разделение:

- клиенту уходит короткое безопасное сообщение;
- подробности SQL и внутренние пути идут только в лог.

Например, ошибка SQLite может содержать путь к базе. Пользователь не должен
видеть этот путь.

JSON-ошибки имеют вид:

```json
{
  "error": "такой slug уже существует"
}
```

Компилятор заставляет обработать все варианты `enum`. Это лучше, чем
забыть добавить статус для новой ошибки.

## 12. Аутентификация: `src/auth.rs`

### 12.1 Термины

| Термин | Значение |
|---|---|
| Аутентификация | Кто ты? Проверка логина и пароля |
| Авторизация | Что тебе разрешено? |
| Хеш пароля | Необратимое представление пароля |
| Соль | Случайные данные, чтобы одинаковые пароли имели разные хеши |
| Сессия | Серверная запись о входе |
| Cookie | Небольшие данные, которые браузер присылает обратно |
| Middleware | Код вокруг запроса: проверить и пропустить либо остановить |

### 12.2 Настройки

```text
ADMIN_USER=editor
ADMIN_PASSWORD_HASH=$argon2id$...
SESSION_COOKIE_SECURE=false
```

В production `SESSION_COOKIE_SECURE=true`, потому что сайт работает по HTTPS.
Локально по HTTP значение `true` не даст браузеру сохранить cookie.

Если логин и хеш не заданы, публичная часть продолжает работать, но вход
возвращает `503`. Это fail closed: отсутствие настройки не открывает доступ.

### 12.3 Создание хеша

Пароль не передают аргументом команды: аргументы видны другим процессам
и могут попасть в историю shell.

Безопасный порядок:

1. запустить `cargo run --bin hash-password`;
2. ввести пароль в stdin;
3. скопировать один Argon2id-хеш в `ADMIN_PASSWORD_HASH`;
4. сам пароль нигде не сохранять.

Argon2 намеренно медленный. Это защищает от массового подбора паролей.

### 12.4 Вход

`POST /api/admin/login`:

1. проверяет размеры username/password;
2. проверяет лимит попыток;
3. читает env;
4. разбирает Argon2 PHC-строку;
5. проверяет пароль;
6. создаёт 32 случайных байта;
7. отправляет браузеру токен в hex;
8. сохраняет в SQLite только SHA-256 токена;
9. ставит cookie на 12 часов.

### 12.5 Cookie

Флаги:

- `HttpOnly` — JavaScript страницы не может прочитать cookie;
- `SameSite=Lax` — чужие сайты не смогут удобно отправлять cookie
  с большинством межсайтовых запросов;
- `Secure` — cookie только по HTTPS в production;
- `Path=/` — cookie доступна всему сайту, не только `/api`.

### 12.6 Middleware

`require_session`:

1. читает cookie;
2. хеширует токен;
3. ищет неистёкшую сессию;
4. вызывает `next.run(request)`;
5. если сессии нет — возвращает `401`.

### 12.7 Зачем `Arc<Mutex<...>>`

Лимит попыток входа — изменяемая таблица в памяти.

- `Arc` позволяет нескольким запросам ссылаться на одну таблицу;
- `Mutex` разрешает менять её только одному потоку одновременно.

Блокировка удерживается коротко. Нельзя держать её во время проверки
Argon2 или запроса к базе.

### 12.8 Почему не JWT

Для одного небольшого сервера JWT добавляет сложность: подпись, срок жизни,
отзыв токена. Сессия в SQLite проще и позволяет сразу отозвать вход через
`logout`.

## 13. Admin API: `src/api.rs`

Все маршруты, кроме login, проходят проверку сессии.

### 13.1 Endpoint-таблица

| Метод и путь | Действие |
|---|---|
| `POST /api/admin/login` | Войти |
| `POST /api/admin/logout` | Выйти |
| `GET /api/admin/me` | Проверить текущую сессию |
| `GET /api/admin/articles` | Список статей |
| `GET /api/admin/articles/{id}` | Полная статья для формы |
| `POST /api/admin/articles` | Создать черновик |
| `PUT /api/admin/articles/{id}` | Сохранить изменения |
| `POST /api/admin/articles/{id}/publish` | Опубликовать |
| `POST /api/admin/articles/{id}/unpublish` | Снять с публикации |
| `DELETE /api/admin/articles/{id}` | Удалить |

### 13.2 Две структуры статьи

`ArticleSummary` используется в таблице. В ней нет `body_md`, потому что
список из десятков статей не должен передавать десятки полных текстов.

`AdminArticle` — полная запись для редактора.

Без `serde::Serialize` структуру нельзя автоматически превратить в JSON.
Без `Deserialize` JSON нельзя автоматически превратить во входную структуру.

### 13.3 Валидация

Проверяется:

- заголовок не пустой и не длиннее 200 символов;
- автор не длиннее 100;
- лид не длиннее 500;
- Markdown не больше 200 КБ;
- рубрика входит в `RUBRICS`;
- slug после нормализации не пустой и не длиннее 120.

Проверка на клиенте улучшает интерфейс, но сервер всё равно проверяет всё
заново. Клиент можно обойти.

### 13.4 Создание slug

Если slug пуст, он генерируется из заголовка. Если редактор ввёл slug
вручную, он нормализуется через тот же `translit`.

Изменение заголовка не меняет slug автоматически: URL уже мог быть
опубликован и проиндексирован.

### 13.5 Публикация

Публикация:

```sql
published = 1,
published_at = date('now')
```

Снятие ставит `published = 0`. Сама запись и текст не удаляются.
Повторная публикация обновляет дату.

### 13.6 Примеры `curl`

Проверка сессии:

```sh
curl -b cookies.txt http://127.0.0.1:8099/api/admin/me
```

Создание:

```sh
curl -b cookies.txt \
  -H 'Content-Type: application/json' \
  -d '{"title":"Заголовок","slug":"","rubric":"Школа",
       "author":"Автор","lead":"Лид","body_md":"Текст"}' \
  http://127.0.0.1:8099/api/admin/articles
```

Удаление:

```sh
curl -b cookies.txt -X DELETE \
  http://127.0.0.1:8099/api/admin/articles/1
```

CSRF-заголовок будет добавлен на следующем этапе безопасности. До этого
API защищён сессией, но мутации ещё не имеют финальной CSRF-защиты.

## 14. HTML-шаблоны minijinja

### 14.1 Наследование

Страница статьи начинается так:

```jinja
{% extends "layout.html.jinja" %}
```

`layout` содержит общую шапку, навигацию и подвал. Дочерний шаблон
заполняет блоки:

```jinja
{% block title %}...{% endblock %}
{% block content %}...{% endblock %}
```

### 14.2 Условия и циклы

```jinja
{% if hero %}
  ...
{% endif %}

{% for article in cards %}
  ...
{% endfor %}
```

Это похоже на JavaScript, но выполняется на сервере до отправки HTML.

### 14.3 Автоэкранирование

Обычно minijinja экранирует `<`, `>` и кавычки. Это защищает от XSS.
Фильтр `safe` отключает экранирование и допустим только для доверенного,
уже очищенного HTML.

### 14.4 Почему шаблоны не знают SQL

Шаблон получает готовые значения. SQL, права доступа и правила публикации
живут в Rust. Если положить бизнес-логику в HTML, её будет трудно тестировать
и легко обойти.

## 16. JavaScript и Vue для новичка

### 16.1 JavaScript — не Java

Минимум для админки:

```js
const title = "Текст";
let count = 0;
```

- `const` — переменную нельзя переназначить;
- `let` — можно;
- объект создаётся как `{ title, slug }`;
- массив — `["Школа", "Спорт"]`;
- функция — `function save() {}` или `const save = () => {}`;
- модуль экспортирует через `export`, импортирует через `import`.

### 16.2 Promise и async/await

HTTP-запрос занимает время. `fetch` возвращает `Promise`.

```js
const response = await fetch("/api/admin/me");
const data = await response.json();
```

`await` можно использовать только внутри `async`-функции.

### 16.3 Почему проверяют `response.ok`

`fetch` не бросает исключение на ответ `401` или `500`. Он успешно получил
HTTP-ответ. Поэтому код обязан проверить:

```js
if (!response.ok) {
  throw new Error("HTTP " + response.status);
}
```

### 16.4 Что будет в `api.js`

Все запросы пойдут через один модуль. Он:

- добавляет `credentials: "include"`;
- добавляет `Content-Type: application/json`;
- добавляет CSRF-заголовок для POST/PUT/DELETE;
- разбирает JSON-ошибку;
- на 401 отправляет на login;
- не повторяет одну и ту же обработку в каждом экране.

Относительные URL вроде `/api/admin/me` нужны, чтобы Vite proxy работал
локально, а production использовал тот же домен.

### 16.5 Vue: минимальная модель

Vue-компонент — кусок интерфейса с HTML, JS и стилями.

`script setup` — современный короткий синтаксис.

`ref` создаёт реактивное значение. Когда оно меняется, Vue обновляет экран.

`computed` создаёт вычисляемое значение из `ref`.

`onMounted` запускает загрузку после появления компонента.

`v-model` связывает поле формы со значением.

`v-if` показывает блок по условию.

`v-for` повторяет элемент для массива.

### 16.6 Vue Router

Маршруты админки:

```text
/admin/login
/admin/articles
/admin/articles/new
/admin/articles/:id
```

`/:id` — параметр. Для `/admin/articles/12` он равен `12`.

Перед внутренними экранами router вызывает `/api/admin/me`. При `401`
пользователь попадает на login.

### 16.7 Vite

В разработке:

- Vite обслуживает Vue на отдельном dev-порту;
- `/api` проксируется в Rust;
- изменения Vue обновляют браузер без перезагрузки Rust.

В production:

- `npm run build` создаёт HTML, JS и CSS;
- они попадают в `static/admin/`;
- Rust отдаёт эти файлы;
- dev-сервер Vite больше не нужен.

`static/admin/` не коммитится: исходники находятся в `admin/`, сборка
воспроизводится командой.

### 16.8 `md-editor-v3`

Компонент даёт поле Markdown и предпросмотр. Для картинок используется
`onUploadImg`: редактор передаёт файлы функции, функция вызывает
`/api/admin/uploads`, получает URL и возвращает его в Markdown.

Публичная страница всё равно заново очищает Markdown через ammonia.
Предпросмотр в браузере не заменяет серверную защиту.

### 16.9 Текущее состояние фронтенда

На момент этого гайда каталога `admin/` ещё нет. Подготовлены backend auth
и JSON API. Следующий этап после отдельного разрешения — создать Vue-проект,
не меняя публичную SSR-часть.

## 18. Как читать ошибки компилятора

Порядок:

1. читать первую ошибку, а не последнюю;
2. смотреть файл и строку;
3. понять, чего не хватает: типа, импорта, ссылки, поля;
4. прочитать подсказку `help`;
5. исправить одну причину;
6. снова запустить `cargo check`.

Частые сообщения:

| Сообщение | Смысл |
|---|---|
| `cannot find type` | Не импортирован тип или неверный путь |
| `mismatched types` | Ожидался другой тип |
| `borrowed value does not live long enough` | Ссылка живёт дольше данных |
| `value moved here` | Владение уже передано |
| `trait bound not satisfied` | Тип не реализует нужную возможность |
| `unused import` | Импорт не нужен |
| `unreachable pattern` | Ветка `match` никогда не выполнится |

Нельзя исправлять ошибку вслепую добавлением `.clone()`, `unwrap()` или
`allow`. Сначала объяснить причину своими словами.

`unwrap()` опасен в обработчике: он превращает ожидаемую ошибку в панику.
В проекте нормальные ошибки идут через `?` и `AppError`.

## 19. Тесты и ручная проверка

### Автоматические тесты

Сейчас проверяются:

- транслитерация рубрик и заголовков;
- Argon2 hash/verify;
- стабильность SHA-256 токена;
- hex-преобразование;
- генерация пустого slug;
- отказ неизвестной рубрики.

### Unit-тест

Проверяет одну функцию без HTTP и базы. Быстрый и точный.

### Smoke-тест

Проверяет главный пользовательский сценарий:

1. поднять сервер на временной базе;
2. войти;
3. создать черновик;
4. убедиться, что публичный URL даёт 404;
5. опубликовать;
6. убедиться, что URL даёт 200;
7. снять с публикации;
8. удалить;
9. получить 404.

Автоматический вариант: `./scripts/smoke.sh`. Он сам создаёт временную БД,
запускает сервер на порту 18081 и удаляет тестовые данные после завершения.

Уже проверено вручную:

- login `200`;
- `/me` с cookie `200`;
- `/me` без cookie `401`;
- logout `200`;
- после logout `/me` `401`;
- создание статьи `201`;
- черновик снаружи `404`;
- публикация и страница `200`;
- дубликат slug `409`;
- удаление `204`;
- удалённая статья `404`.

## 20. Безопасность простыми словами

### SQL-инъекция

Лечится `.bind`, а не склейкой SQL-строк.

### XSS

Опасный HTML из Markdown лечится ammonia. `|safe` применяется только после
очистки.

### Кража пароля

Пароль не хранится. Хранится медленный Argon2id-хеш со случайной солью.

### Кража сессии

Токен случайный, в БД лежит его хеш, cookie `HttpOnly` и `Secure` в проде.

### CSRF

Скоро будет обязательный кастомный заголовок для мутаций. Чужой обычный
сайт не сможет отправить такой заголовок без CORS preflight. В проекте
CORS не открыт.

### Подбор пароля

Пять неудачных попыток на 15 минут по имени пользователя.

### Огромный запрос

Для формы и upload будут отдельные лимиты тела. Значение по умолчанию
не должно позволять забить память.

### Опасная загрузка

Тип определяется по содержимому. SVG, HTML и исполняемые файлы запрещены.
Расширению от клиента нельзя доверять.

### Секреты

Настоящий `.env` и `deploy/vivec.env` не коммитятся. В репозитории только
пример без реальных значений.

- удаление веток;
- коммит данных, секретов и сборок.

Текущее состояние на момент гайда:

- публичная часть влита в `main`;
- auth влит в `main`;
- API готов и проверен в `feature/admin-api`;
- этот гайд добавляется документационным коммитом;
- `main` опережает `origin/main`, push не выполнялся.

## 22. Контейнер и сервер

Контейнер собирается локально:

```sh
podman build -t vivec:latest .
```

На сервер передаётся готовый образ. Сервер с 1 ГБ не должен собирать Rust:
компилятор может быть убит из-за нехватки памяти.

Данные монтируются в `/data`.

Rootless podman требует:

```text
--userns=keep-id:uid=10001,gid=10001
```

Иначе uid пользователя на хосте не совпадёт с uid контейнера, и SQLite не
сможет писать файл.

Снаружи порт слушает только loopback:

```text
127.0.0.1:8081 → контейнер:8080
```

Caddy принимает HTTPS и проксирует запросы на 8081.

Перед изменением сервера нужен аудит:

- ОС и init;
- занятые порты;
- Caddyfile;
- DNS;
- SELinux;
- память и диск.

Нельзя перезаписывать существующий Caddyfile целиком: на сервере может
работать 3x-ui и другие сайты.

## 23. Как учиться на этом проекте

### Правило 30 строк

Не брать в работу кусок кода больше 30 строк, который не можешь пересказать.

Порядок:

1. прочитать функцию;
2. объяснить её вход;
3. объяснить выход;
4. объяснить одну главную идею;
5. назвать возможную ошибку;
6. только потом менять.

### Упражнение на понимание

Для каждой функции ответить:

- кто её вызывает;
- какие данные приходят;
- что она меняет;
- что возвращает при успехе;
- что возвращает при ошибке;
- как проверить результат.

### Мини-задания

1. В `slug.rs` добавить тест для строки `«Ёлка»!` и объяснить результат.
2. В `articles.rs` объяснить, почему `by_rubric` фильтрует в Rust.
3. В `error.rs` объяснить, почему SQL-ошибка не отдаётся клиенту.
4. В `auth.rs` объяснить разницу между токеном cookie и `token_hash`.
5. В `api.rs` объяснить, почему DELETE возвращает 204 без JSON.
6. В шаблоне 404 добавить учебную фразу, собрать и проверить `curl`.
7. В браузере открыть главную на 1200 и 390 px и назвать три изменения.

### Дневной цикл

```text
прочитать TODO
→ выбрать одну маленькую задачу
→ прочитать связанный код
→ сформулировать изменение
→ изменить
→ cargo fmt/check/test/clippy
→ запустить
→ curl или браузер
→ обновить TODO и journal
→ коммит
```

Если задача не влезает в 2–3 часа, её надо резать, а не героически
оставлять недоделанной.

| Слово | Перевод и смысл |
|---|---|
| Backend | Серверная часть |
| Frontend | Интерфейс в браузере |
| Handler | Функция обработки запроса |
| Router | Таблица «URL → handler» |
| Middleware | Проверка до или после handler |
| State | Общие данные приложения |
| Pool | Пул соединений БД |
| Row | Одна строка SQL-результата |
| Commit | Зафиксированное изменение git |
| Branch | Отдельная линия изменений |
| Merge | Слияние веток |
| Build | Полная сборка |
| Check | Быстрая проверка типов |
| Clippy | Линтер Rust |
| Unit test | Тест одной функции |
| Smoke test | Короткая проверка главного сценария |
| Runtime | Среда выполнения |
| Async | Неблокирующее ожидание |
| API | Интерфейс для программных запросов |
