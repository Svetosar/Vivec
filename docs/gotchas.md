# Грабли Vivec

Накопитель конкретных ловушек: симптом → причина → фикс. Пополняется по факту, не по памяти.
**Статус обязателен:** `проверено` (воспроизвели и починили), `гипотеза` (ожидаем, но не проверяли), `решение` (осознанный выбор, не баг).

Формат записи:

```
### G-000 · Короткое имя
Статус: гипотеза | проверено | решение · дата
Симптом: ...
Причина: ...
Фикс: ...
```

### G-001 · axum 0.8: параметр пути пишется `{id}`, а не `:id`
Статус: гипотеза · 13.11.2026
Симптом: маршрут не матчится, 404 или паника при старте.
Причина: в axum 0.8 сменился синтаксис параметров пути.
Фикс: `.route("/article/{slug}", ...)`. Проверить компилятором и докой при первом маршруте (16.11).

### G-002 · ammonia вырезает `class` и относительные `src`
Статус: гипотеза · 13.11.2026
Симптом: картинки в статьях ломаются, CSS-классы из markdown исчезают.
Причина: санитайзер по умолчанию не пропускает часть атрибутов и относительные URL.
Фикс: настроить allow-list тегов/атрибутов и `UrlRelative::PassThrough`. Проверить 17.11 на реальной статье с картинкой.

### G-003 · minijinja: HTML из markdown не рендерится без `|safe`
Статус: гипотеза · 13.11.2026
Симптом: в статье видны теги как текст.
Причина: автоэкранирование шаблонизатора.
Фикс: `{{ body_html|safe }}` — и только для уже очищенного `ammonia` HTML.

### G-004 · sqlx runtime-запросы падают в рантайме, а не при компиляции
Статус: решение + риск · 13.11.2026
Симптом: приложение компилируется, но 500 на странице из-за несовпадения колонки и поля.
Причина: осознанный отказ от `query!`-макросов (они требуют `DATABASE_URL` на этапе сборки).
Фикс: имена колонок в `SELECT` = имена полей структуры с `#[derive(FromRow)]`. Любой новый запрос — сразу дёрнуть `curl`.

### G-005 · `include_str!`: правка шаблона требует пересборки
Статус: решение · 13.11.2026
Симптом: поправил HTML, а на странице старое.
Причина: шаблон вкомпилирован в бинарник.
Фикс: `cargo run` заново (5–10 с). Взамен — нет «файл не найден» в контейнере.

### G-006 · rootless podman: контейнер не поднимается после ребута
Статус: гипотеза · 13.11.2026
Симптом: после перезагрузки сервис неактивен.
Причина: без linger пользовательские юниты не стартуют при загрузке.
Фикс: `loginctl enable-linger <user>`. Проверить 15.11 реальным `reboot`.

### G-007 · права на `data/` при rootless + bind mount
Статус: гипотеза · 13.11.2026
Симптом: SQLite не может создать файл / `disk I/O error`.
Причина: UID-маппинг rootless-контейнера не совпадает с владельцем каталога.
Фикс: `:Z` для SELinux, `:U` для владельца, либо разовый `chown` под маппленный UID. Проверить 15.11.

### G-008 · Caddy и ACME: лишняя AAAA-запись ломает сертификат
Статус: гипотеза · 13.11.2026
Симптом: `caddy` не может получить сертификат, в логах ошибка challenge.
Причина: AAAA указывает на другой хост.
Фикс: `dig A` + `dig AAAA` до правки Caddyfile. При экспериментах — staging-CA.

### G-009 · Сборка Rust на сервере 1 ГБ

Фикс: собирать только локально, на сервер возить образ. `podman build` на сервере запрещён.

### G-010 · Vite dev + cookie-сессия
Статус: гипотеза · 13.11.2026

### G-011 · Zed на Gentoo: бинарь называется `zedit`

### G-012 · VS Code watcher жрёт CPU на `target/`
Статус: решение · 13.11.2026
Симптом: после каждого `cargo build` редактор нагружает диск и греет ядро.
Причина: в `target/` десятки тысяч файлов.
Фикс: `files.watcherExclude` и `search.exclude` для `target/`, `node_modules/`, `static/admin/`, `data/` — уже в `.vscode/settings.json`.

### G-013 · minijinja-шаблоны без подсветки
Статус: решение · 13.11.2026
Симптом: `{% block %}` и `{{ var }}` выглядят как обычный текст.
Фикс: файлы называются `*.html.jinja`, в настройках `"files.associations": {"*.html.jinja": "jinja-html"}`, расширение `samuelcolvin.jinjahtml`. Путям в `include_str!` это не мешает.

### G-014 · COPY сохраняет mtime → в образ попадает пустой бинарник
Статус: проверено · 13.11.2026
Симптом: `podman build` успешен, контейнер стартует, `exit 0`, логи пустые, HTTP не отвечает.
Причина: слой с зависимостями собирается с заглушкой `fn main() {}`. Затем `COPY src` приносит исходники со mtime **старше** артефакта, cargo считает их неизменёнными и не пересобирает. В финальный слой уезжает заглушка.
Фикс: после `COPY src templates` выполнять `find src templates -type f -exec touch {} +` перед `cargo build --release`. Обязательно проверять контейнер запуском, а не сообщением «Successfully tagged».

### G-015 · `podman stats` показывает память всего пользовательского cgroup
Статус: проверено · 13.11.2026
Симптом: `podman stats` для пустого axum-контейнера показывает ~9.8 ГБ.
Причина: у rootless-контейнера учёт идёт по родительскому cgroup, а не по процессу.
Фикс: мерить реально — `podman inspect --format '{{.State.Pid}}'` + `grep VmRSS /proc/<pid>/status`. Фактическое потребление пустого сервиса: **5,3 МБ RSS** (VmSize 271 МБ — виртуальная, не считается).

### G-016 · Без обработчика SIGTERM каждый рестарт — 10 секунд простоя
Статус: проверено · 13.11.2026
Симптом: `podman stop` висит 10 секунд, затем `SIGKILL failed to stop container`, соединения обрываются.
Причина: `axum::serve` без `with_graceful_shutdown` не реагирует на SIGTERM.
Фикс: `shutdown_signal()` с `tokio::select!` на `ctrl_c` и `SignalKind::terminate`, плюс `with_graceful_shutdown(...)`. После фикса остановка — 156 мс.

### G-017 · MCP-сервер FigCraft живёт ~52 секунды и получает SIGKILL
Статус: проверено · 14.11.2026
Симптом: `opencode mcp list` → `✗ figcraft failed: MCP server process exited with code 137`, инструменты пропадают из сессии. Через `timeout`/ `status` воспроизводится: после `mcp connected` сервер умирает через **51 и 53 секунды** (два замера подряд), без единого запроса.
Что проверено и отвергнуто:
- не память: `oom_kill` в `/proc/vmstat` = 0, `free` 7 ГБ, `/proc/pressure/memory` = 0;
- не закрытие окна FigCraft: headless-сервер стартует и отвечает при полностью закрытом приложении;
- не конфликт двух экземпляров: два параллельных `flatpak run ... mcp` прожили 40 с и вышли с кодом 0;
- не битый бинарник: та же команда вручную отдаёт `initialize` и 19 инструментов;
- не простой: экземпляр с открытым stdin прожил 600 с.
OpenCode после падения **не перезапускает** сервер: в `~/.local/share/opencode/log/opencode.log` новых строк `mcp connected` нет, `touch opencode.json` не помогает.
Временный обход: изменить **содержимое** `opencode.json` → переподключение на ~50 секунд. Рабочий путь без MCP: `figcraft-cli run <script.json>` — создаёт слои, сохраняет, отдаёт скриншот и CSS.
Причина не установлена. Следующая гипотеза для проверки: клиентский `ping`/таймаут на стороне OpenCode.


### G-018 · Локальный запуск падает: `Address already in use` на 8080
Статус: проверено · 14.11.2026
Симптом: `./target/debug/vivec` → `Error: Address already in use (os error 98)`, при этом `curl http://127.0.0.1:8080/` отдаёт чужую страницу («CEF remote debugging»).
Причина: порт 8080 на рабочей машине занят `steamwebhelper` (`ss -tlnp` → `127.0.0.1:8080`, users:(("steamwebhelper"))). Наш bind `0.0.0.0:8080` конфликтует с чужим loopback-сокетом.
Фикс: порт читается из `PORT` (по умолчанию 8080). Локально: `PORT=8099 cargo run`. Для прода порт хоста задаётся при публикации: `podman run -p 127.0.0.1:8081:8080`.

### G-019 · FigCraft: у созданных через CLI слоёв «застывшие» высоты
Статус: проверено · 14.11.2026
Симптом: текст в макете обрезан по одной строке, секции налезают друг на друга, хотя `fontSize`, `gap`, `padding` заданы верно.
Причина: `node.create` считает бокс в момент создания. Если задать ширину позже (или текст переносится), высота не пересчитывается; авто-лейаут-фреймы тоже хранят высоту, посчитанную при рождении.
Фикс: явно `textAutoResize: "height"` для текста с фиксированной шириной (или `sizingH: "fill"`), и `sizingV: "hug"` для всех вертикальных фреймов и артбордов. После этого дерево пересобирается снизу вверх.
Побочное: id слоёв в FigCraft идут строго по порядку, поэтому генератор скрипта может предсказывать id для `parent`. Проверено на 104 командах — совпало 1:1.

### G-020 · Стили статьи «съезжают» на 40 px: дефолтные отступы браузера
Статус: проверено · 14.11.2026
Симптом: `<figure>` и `<blockquote>` шире остальных абзацев и смещены вправо, хотя CSS их не трогает.
Причина: браузерный `user-agent` стиль `margin: 1em 40px` у `figure` и `blockquote`. Сброс только `p` и `h1..h3` этого не покрывает.
Фикс: `figure, blockquote { margin: 0; }`. Проверять макет в браузере, а не только в редакторе дизайна.

### G-021 · Контейнер не может открыть базу на примонтированном каталоге
Статус: проверено · 15.11.2026
Симптом: `podman run -v /tmp/opencode/vdata:/data vivec:local` → контейнер падает, в логах
`(code: 14) unable to open database file`, `/ → 000`. Сам каталог на хосте пустой.
Причина: в образе `USER 10001`. В rootless podman uid 10001 внутри контейнера — это не uid
хоста, а сабьюид (например, 100999). Каталог на хосте принадлежит моему uid (1000), прав на
запись у сабьюида нет.
Проверка: `podman run --rm -v …:/data … sh -c 'id; ls -ld /data'` → `uid=10001(vivec)`,
`/data` — `root root`. А `podman unshare ls -ln /tmp/opencode/vdata` показывает `0 0`.
Фикс (проверено): `--userns=keep-id:uid=10001,gid=10001` — uid хоста (1000) отображается на
uid 10001 внутри, каталог становится `vivec:vivec`, запись идёт.
Проверено end-to-end: приложение создаёт схему (`база готова: /data/vivec.db`), `/ → 200`
«Пока пусто» на пустой базе; после `sqlite3 … < migrations/seed.sql` — 4 статьи на главной,
`/remont-sportzala → 200`. На хосте `vivec.db`, `-shm`, `-wal` принадлежат моему uid.
Альтернатива без флага (не выбрана): `chown` каталога под uid из `podman unshare id` или
пользователь в образе с uid хоста. Флаг проще: он же нужен и на сервере.
Важно для деплоя: на сервере `/srv/vivec/data` создаёт тот же флаг — см. `docs/deploy.md` §2.

### G-022 · minijinja 3.x: `Value::from_serialize` удалён, `context!` берёт только `Into<Value>`
Статус: проверено · 14.11.2026
Симптом: `minijinja::context! { article => article }` → `the trait bound minijinja::Value: From<Article> is not satisfied`. Попытка `Value::from_serialize(...)` → `no function or associated item named from_serialize`.
Причина: в 3.0 serde стал опциональным (`features = ["serde"]`), `Value::from_serialize` убран,
`context!` и `render()` конвертируют только через `Into<Value>` (см. CHANGELOG, #528).
Фикс: включить фичу `serde` и обернуть контекст: `Value::from(minijinja::value::Serde(ctx))`,
где `ctx` — своя структура с `#[derive(Serialize)]`. Так же пришлось поменять `FromRow`-подход:
строки разбираются через `Row::try_get` (макросы в проекте запрещены).

### G-023 · pulldown-cmark без default-features не умеет HTML
Статус: проверено · 15.11.2026
Симптом: `use pulldown_cmark::{html, Options, Parser};` → `no 'html' in the root`,
подсказка «found an item that was configured out … gated behind the `html` feature».
Причина: поставил `default-features = false`, а модуль `html` в 0.13 опционален.
Фикс: `features = ["html"]`. Итог: `pulldown-cmark = { version = "0.13.6", default-features = false, features = ["html"] }`.
Побочное: `ammonia 4.2.5` тянет `html5ever`/`markup5ever` — release-сборка в контейнере
занимает ~3 минуты (было ~2). Это цена за настоящий HTML-парсер в санитайзере.

### G-024 · `ServeDir::not_found_service` всегда возвращает 404 для SPA
Статус: проверено · 17.11.2026
Симптом: `/admin/articles` отдаёт HTML приложения, но HTTP-код 404; роутер Vue после
загрузки уже не успевает исправить статус.

Проверено: `/admin/articles` → `200`, реальный `/admin/assets/...` → `200`.

### G-025 · create-vue поставил vue-router 5 с уязвимым build-деревом
Статус: решение · 17.11.2026

### G-026 · md-editor-v3 оставляет split-preview на мобильной ширине

### G-027 · SQLite LIKE/NOCASE не меняет регистр кириллицы
Статус: проверено · 18.11.2026
Симптом: поиск `РЕМОНТ` не находит статью, в тексте которой написано `Ремонт`, если
полагаться на SQLite `LIKE` или `COLLATE NOCASE`.
Причина: встроенные сравнения SQLite без ICU корректно складывают регистр только для ASCII.
Фикс для v1: получить опубликованные строки и выполнить Unicode `to_lowercase().contains()`
в Rust. Проверено: верхний и нижний регистр дают одинаковый результат, черновик не попадает
в выдачу. FTS5 `trigram` остаётся после сдачи.

### G-028 · podman-compose ломает `$` в Argon2-хеше из `environment`

### G-029 · `CARGO_NET_OFFLINE` из `podman build --env` попадает в runtime
Статус: проверено · 18.11.2026
Симптом: в `podman image inspect` финального образа видна сборочная переменная,

### G-030 · OCI-образ молча теряет Docker HEALTHCHECK
Статус: проверено · 18.11.2026
Симптом: `HEALTHCHECK` указан в Containerfile, но Podman предупреждает, что он
не поддерживается OCI-форматом; в опубликованном образе проверки нет.
Причина: Docker healthcheck хранится в конфигурации Docker-манифеста, а OCI
image config не переносит его автоматически.
Фикс: для образа с healthcheck собирать `podman build --format docker`; после
публикации проверять `.Config.Healthcheck` в `podman image inspect`.
