# Vivec 0.1.0 alpha

Дата подготовки: 18.11.2026.

Это первый тестовый релиз. Публичный SSR-сайт, мини-CMS, загрузка изображений,
поиск и архив уже собраны в один Linux x86_64 Alpine/musl image. Реальные
проверки на школьном сервере ещё предстоят: текущий статус — **alpha**, не
production.

Опубликованные теги: `svetosar/vivec:0.1.0` и `svetosar/vivec:latest`.
Digest: `sha256:fc64f8dec3c336f5fd40a7f315b5add7c875efc96350424383bfd671ef7676f0`.

## Что входит в релиз

- Rust + axum + SQLite: публичные страницы, статьи, рубрики, поиск и архив.
- Vue 3 + Vite: вход, список статей, редактор Markdown и загрузка картинок.
- Безопасность: Argon2, серверные сессии, CSRF-заголовок, санитайзинг Markdown,
  ограничения загрузок и лимиты логина.
- SEO и эксплуатация: meta/Open Graph, canonical, robots.txt, sitemap.xml,
  `/healthz`, security headers и кэш-политики.
- Контейнер: Alpine/musl, non-root UID 10001, read-only совместимость,
  Docker healthcheck, OCI-метки и закреплённые digest базовых образов.

## Что нужно сделать перед реальным сервером

Это блокеры для beta, но не для публикации образа:

1. Провести аудит сервера: ОС, init, DNS, SELinux, порты Caddy и 3x-ui.
2. Проверить site-блок Caddy на самом сервере; локальной Caddy в проекте нет.
3. Развернуть через Quadlet, проверить TLS, `/healthz`, вход и сохранение статьи.
4. Убедиться, что панель 3x-ui и VPN не затронуты.
5. Настроить offsite-бэкап и проверить восстановление на реальном хосте.
6. Задать `PUBLIC_ORIGIN`, настоящий `ADMIN_PASSWORD_HASH`,
   `SESSION_COOKIE_SECURE=true`, `TRUST_PROXY=true`, `VIVEC_SEED_DEMO=0`.
7. Провести нагрузочный тест на 1 ГБ RAM после появления сервера.

## Известные ограничения

- Лимиты логина хранятся в памяти и сбрасываются при рестарте.
- Поиск не индексирует тело статьи: только заголовок, автор, лид и метаданные.
- Загрузка до 8 МиБ буферизуется до записи на диск.
- Один аккаунт редактора; привязки сессии к имени пользователя нет.
- Очистка `/uploads` выполняется при обновлении/удалении статьи, а не по cron.
- Git remotes проекта не совпадают с именем Docker Hub repository; перед
  `git push` проверить адрес отдельно.
