# Журнал проекта Vivec

Память проекта: факты, решения и уроки. Не пересказ кода — пересказ кода есть в git.

## Правила ведения

1. Запись в конце **каждой** рабочей сессии. 5 минут, не больше.
2. Формат: сделано → новое → сломалось → урок → что дальше.
3. Старые записи **не переписывать**. История важнее красоты.
4. Подтверждённые грабли — в `docs/gotchas.md`.
5. Грабли, повторившиеся дважды, — в скилл `vivec`, чтобы не наступать третий раз.
6. Никаких выводов по памяти: пишем только то, что запускали или читали в доке.

## 2026-11-13 — план, стек и правила

**Сделано**
- Зафиксирован план на 17 дней (14.11–30.11), бюджет 2–3 ч/день.
- Выбран стек: axum + SQLite/sqlx + minijinja, публичка SSR, админка на Vue 3.
- Деплой: локальная сборка → `podman save | ssh | podman load` → Quadlet → Caddy.
- Созданы: скилл `vivec`, `AGENTS.md`, `TODO.md`, `docs/backlog.md`, `.gitignore`.
- Ветка `chore/agent-rules`, `main` не тронут.

**Решения**
- Публичная часть без JS-фреймворка (SEO, старые телефоны, устойчивость).
- Vue только в админке: `md-editor-v3` даёт редактор с предпросмотром и загрузкой картинок.
- UI-кит не берём (PrimeVue отклонён): настройка дороже пяти ручных компонентов.
- Поиск стартует на `LIKE`; FTS5 — только при наличии буфера.
- Даты в БД — `TEXT` + `datetime('now')`, без `chrono` в структурах.
- Шаблоны через `include_str!` — нет проблем с путями в контейнере.
- Скоуп заморожен 26.11. Новое — в backlog.

**Что нового**
- Фреймворк сам по себе не создаёт задел. Задел — это JSON API, markdown-контент, стабильная схема БД и раздельные слои. Фреймворк можно навесить потом.
- `podman save | ssh | podman load` заменяет registry для одного хоста.
- Quadlet — нативный способ поднять контейнер из systemd, без `podman generate systemd`.
- Сборка на сервере с 1 ГБ — источник OOM, поэтому собираем локально.

**Что проверить (не выдумывать)**
- ОС и init-система сервера; есть ли systemd.
- Поддомен и DNS; текущие site-блоки Caddy; где слушает панель 3x-ui.
- SELinux на сервере (влияет на `:Z` / `:U`).
- Один админ или несколько редакторов.

**Урок**
Главный риск проекта — не синтаксис Rust, а расползание объёма. Защита — даты и список «не делаем», а не обещания «успею».

## 2026-11-13 — выбор редактора

**Сделано**
- Основной редактор проекта: **VS Code 1.145.0**.
- Проверено, что установлено: VS Code + rust-analyzer, crates, rust-syntax, GitLens, Git History, containers, html-css.
- Доустановлено и проверено по версиям: `vue.volar` 3.3.14, `vadimcn.vscode-lldb` 1.12.3, `tamasfe.even-better-toml` 0.21.2, `qwtel.sqlite-viewer` 26.9.1, `samuelcolvin.jinjahtml` 0.20.0, `usernamehw.errorlens` 3.30.0, `esbenp.prettier-vscode` 12.4.0.
- В репозиторий добавлены `.vscode/settings.json`, `.vscode/extensions.json`, `.vscode/launch.json`.

**Решения**
- Zed (пакет `app-editors/zed`, бинарь **`zedit`**, не `zed`) — только для быстрых правок и заметок, не для проекта.
- Один редактор на проект до сдачи. Переключение в середине — запрещено, это скрытая потеря часов.
- Шаблоны именуются `*.html.jinja`, чтобы работала подсветка Jinja (`files.associations`).
- `rust-analyzer.check.command = clippy` — ошибки и предупреждения видны в редакторе до сборки.
- `files.watcherExclude` для `target/`, `node_modules/`, `static/admin/`, `data/` — иначе watcher жрёт CPU на каждом `cargo build`.

**Что нового**
- У Zed на Gentoo CLI называется `zedit`; `which zed` ничего не находит, хотя пакет установлен. Проверять `qlist app-editors/zed`, а не PATH.
- Zed технически умеет и Rust-дебаг (DAP/CodeLLDB), и Vue (через `vuejs/language-tools`), то есть выбор был не про «умеет/не умеет», а про стоимость времени.
- `Error Lens` даёт текст ошибки прямо в строке — для новичка в Rust это не украшение, а ускоритель обучения.

**Урок**
Выбор инструмента на 2 недели делается по критерию «сколько часов он сэкономит», а не «что приятнее». Расширения установлены и проверены запуском, а не «должно работать».

**Дальше**
14.11 — каркас на ветке `feature/scaffold`.
